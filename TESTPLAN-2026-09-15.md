## The fix on this branch (commit 23fd048) — needs its own test pass

Root cause: the worker's `room-full` counted OPEN joiner relay sockets, and
every seated joiner closes its relay socket once WebRTC is up. So a running
game with all seats taken looked EMPTY to the relay: it admitted the 5th
client (`joined`), and the in-game host (no parked seat) never offered and
never refused. Only the client's 45 s no-offer timer ended it — and the
#557 cold-invite path (real deep link / Steam Join Game / `+connect`)
didn't run that timer at all, so a deep link into a full game hung forever.

Fix:
- Host sends `{t:"seats", free}` to the relay (`NetSignal::send_seats`;
  lobby = waiting-room free seats, in-game = parked seats the rejoin door
  would serve). `Room.room_full` in `signal/src/worker.js` refuses a fresh
  `/join` with `room-full` when the host says 0 and its socket is open.
  Reclaim forgets the count; host re-sends on the Room frame.
- The client's auto-rejoin sends `?rejoin=1` and is EXEMPT (the host frees
  a lost seat only after its watchdog notices; the rejoiner arrives first).
- Cold invite path now shares the 45 s no-offer timer as a backstop.

Verified locally: `signal/test/room_unit_test.mjs` (pure node) and
`signal/test/capacity_test.mjs` (against `wrangler dev --local`) both green;
`g++ -fsyntax-only` clean. NOT run: the Xvfb netplay e2e suite (CI does it).

To test it: open a PR from this branch; once merged, a master push touching
`signal/` auto-deploys `newtonia-signal-beta` (deploy-signal.yml). The
CLIENT also needs this commit, so test with a desktop build of the branch
(`make`) pointed at beta, not a store build. Production gets the worker on

## Pointing a build at the beta worker

- Desktop/Linux/macOS binary and the Steam Linux build:
  `NEWTONIA_SIGNAL_URL=wss://newtonia-signal-beta.gfmcc.workers.dev/ws`
  in the environment, or `signal_url=...` in the preferences INI. On Steam:
  launch option `NEWTONIA_SIGNAL_URL=... %command%`.
- iOS: dispatch deploy-ios with `signal_worker: beta` (sentinel version,
  cannot reach production rooms; expire it in App Store Connect after).
- Android store build: cannot be redirected; a sideloaded debug APK gets
  no Play install referrer. Android scenarios are production only.
- Add `NEWTONIA_NET_DEBUG=1` on desktop to see the `[lobby]` / `net:` lines.
- Desktop deep-link stand-in: `./newtonia +connect CODE` (same path as a
  tapped link: `capture_launch` → `Menu::tick` → `NetLobby(code,
  InviteAcceptTag)`). Pasting the link on the JOIN screen is the PLAIN
  join path, a different code path — test both where it matters.

## A. Beta worker: cold-invite fast fail (#557)

1. [PASS] **Dead code.** `./newtonia +connect ZZZZZ` against beta →
   "JOINING THE ROOM", then within ~2 s "THE ROOM IS GONE" / "TRY AGAIN OR
   HOST A NEW ROOM". Log has `cold invite failed`, never `rejoin retry in`
   or `rejoin gave up`.
2. [PASS] **Host quit, then invite.** Host on A, copy link, exit to menu on
   A, accept on B → "THE HOST ENDED THE GAME" or "THE ROOM IS GONE" fast.
3. [FAIL → fixed in 23fd048, retest] **Full room.** Host + 3 joiners (the
   room auto-starts at 4), then a 5th client joins.
   - With the fix, via `+connect`: "THAT ROOM IS FULL" in ~1 s, log
     `cold invite failed: THAT ROOM IS FULL`.
   - With the fix, via pasted link / typed code: status "THAT ROOM IS
     FULL", back to code entry.
   - Host log should show `net: seats free 0 reported` once the game
     starts (and `[lobby] seats free N reported` in the waiting room).
   - Without the fix (v1.62.0 store builds): 45 s → "THE HOST IS NOT
     RESPONDING" on the plain path; the cold path hangs forever. Known.
3b. **Rejoin still works with the fix.** In the running 4-player game,
   cut one joiner's network for ~10 s, restore. Expect the joiner's
   auto-rejoin to be admitted (`?rejoin=1` exempt), host log `player N
   lost - room X reopened for rejoin` then `player N rejoined`. Then, while
   that seat is parked (before the rejoin lands), a FRESH 5th client
   joining is ADMITTED by the relay (free=1) and waits — that is today's
   behaviour and expected.
3c. **Host relay drop.** With the game running and full, kill the HOST's
   network for ~20 s (relay socket drops, room in grace), restore. Host
   log `room X reclaimed`, then `seats free 0 reported` again. A 5th
   client joining during the grace window is admitted and waits (count not
   enforced in grace); after the reclaim it is refused.
4. **Silent room.** Point the invite at a relay that accepts the socket
   but never answers (e.g. `wrangler dev` paused in a debugger). Expect
   "THE ROOM IS NOT RESPONDING" after ~12 s, not 60 s.
5. **Spent code stays spent.** After 1 fails, return to the menu with the
   dead link on the clipboard: the clipboard auto-join must refuse it;
   typing the same code by hand must still attempt a join.
6. **Healthy invite unchanged.** Host on A, accept cold on B → plain
   "JOINING THE ROOM", then the waiting room; no "GIVING UP IN N" countdown.
7. **Mid-game rejoin still patient.** Join a live game; kill the host's
   network 20 s; restore. Joiner shows "WAITING FOR THE HOST TO COME BACK"
   with the countdown and reconnects (proves the cold flag didn't leak into
   the rejoin ctor).
8. **Steam friend invite.** Steam beta branch: host on A; on B (game
   closed) use Join Game from the friends list → cold launch lands in the
   waiting room. Repeat after A left the room → fast fail card.
